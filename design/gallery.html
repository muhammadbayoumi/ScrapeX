ScrapeX UI kit

Every reusable component on both surfaces. Look here before writing a new class. Composition beats invention: ghost + compact + icon-button is three rules that already exist, not a fourth that does not.

The rule. class is for styling, and every class in markup must resolve to a rule. JavaScript hooks and test selectors use data-* or id. See docs/UI-KIT.md.

Sizes and icon-only

icon-button is square at the full touch-target size; add compact for a small square. The two were never composable until 2026-08-05 — together they drew a rectangle. xs is the third notch, 32px, added 2026-08-11 for secondary icon controls — a quiet action that must not out-shout the page it sits on. It is under the 44px coarse-pointer floor, so a primary or destructive action never uses it.

Sign in with Google

Not ours to design. Google's branding guidelines fix the background, the stroke, the text colour, the type and the padding, and forbid altering the mark at all — no monochrome version, no substitute icon, and never the icon on its own without the button boundary and text. The three sanctioned strings are Sign in with Google, Sign up with Google and Continue with Google; localisation is allowed, invention is not. The colours are tokens so the button follows the panel between light and dark, which the guidelines permit. Nothing else about it follows anything.

Icon tile

The mark at the head of a summary row, a route, an account, a group, an empty state. It was written three times — fourteen elements across the Exports, Sync and Overview pages — with the same six declarations each time and only the size differing. The size is a custom property the caller sets: a page keeps what makes it different and stops restating what does not. 

<span class="icon-tile"><svg><use href="…#storage"></use></svg></span>
<span class="icon-tile amber">…   warning tone
<span class="icon-tile danger">…  problem tone
<span class="icon-tile quiet">…   neutral tone, for a thing that is not installed

/* .brand-logo inside a tile takes the tile's ink instead of --text: */

/* a page that needs a different size says only that: */

brand

An EMPTY <span>, not an <svg> — the mark is a CSS mask. The surface must define --brand-mark; components.css uses it and does not define it, because each surface points at its own copy of the asset. Forget the token and you get a solid black square.

Source identity

The bilingual name block

One reading order everywhere a source is named: domain, then the English name, then the site's own local name, then the stable key. The unmarked name is English and required; the local name may be absent. Never machine-translated — both are captured as the site wrote them. The Jinja macro is _source_identity.html; keep link/checkbox/cell semantics in the caller and the identity itself identical.

An appearance carries more than colour

Added by R-71. Until then every one of the 36 properties an appearance could set was a colour — shape 0, typography 0, elevation 0, motion 0 — so a palette could repaint the UI and not restyle it. DESIGN_PROPERTIES in design/appearance.js is the second axis, and this is what it reaches. Everything below is drawn from the tokens in force right now, so switching appearance in the panel changes this block — which is the whole claim being made.

radius-xs radius-sm radius radius-lg radius-xl radius-pill
fw-regular — body text at the weight the appearance asks for fw-medium — labels and active states fw-bold — headings fw-heavy — the top of the ramp, which an appearance may flatten font-heading — a second face, if the appearance pairs two font-mono
shadow-xs shadow-sm shadow-lg 
// design/appearance.js
["supabase", {
  design: {                       // scheme-independent: shape, type, motion
    radius: "0.375rem", fwRegular: "450",
    ease: "cubic-bezier(0.16, 1, 0.3, 1)",
  },
  themes: {
    light: { /* colours */ design: {shadowSm: "0 1px 3px var(--shadow-color)"} },
    dark:  { /* colours */ design: {shadowSm: "0 1px 2px var(--shadow-color)"} },
  },
}]
