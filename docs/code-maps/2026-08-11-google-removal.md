### Traps

- loadOutputs() is called from exactly ONE place: loadRunDestination() at app.js:4073, which only runs when the current view is "run" AND the engine is up (4067-4068). showView("settings") (app.js:328-332) calls ensureTimeZoneControl/loadSchedules/loadStorage and NOT loadOutputs. So an owner who opens Settings without ever visiting Run sees the skeleton at app.html:1515 forever. Anything rendered from loadOutputs inherits that bug.
- loadOutputs() replaces $("outputs").innerHTML wholesale (app.js:3498). Any element or listener placed inside #outputs is destroyed on each render — which is precisely why the setup links are re-bound at 3513-3514 after every write. A progress bar living inside #outputs would be wiped mid-upload.
- The google row's action is data-driven: `o.settings_url` comes from the engine (scrapex/outputs.py:536), and the button only exists when that string is non-empty (app.js:3485-3488). Removing the openTab handoff at 3514 without replacing it silently leaves rows with a dead-looking "Set it up" button.
- The output key is "google_drive" (scrapex/outputs.py:34), and the sync group is selected NEGATIVELY — `key !== "local_db" && key !== "excel"` (app.js:3497). A filter for "google" matches nothing, and any new engine-side key lands in "Synchronization services" whether or not that is where it belongs.
- google_status().ready (scrapex/outputs.py:429-447) reflects the ENGINE's own OAuth token file on disk plus the googleapiclient import — it has nothing to do with state.token. A panel feature using chrome.identity will work while the row still reads "Needs setup", and vice versa. The two Google identities must not be conflated in copy.
- state.token is memory-only and is cleared from five places (app.js:2265, 2288, 2309, 2348, 4309). A long upload holds a token that sign-out has already revoked; drive.js's convention is to take it as an argument per call (drive.js:75-82 throws a named "no-token" DriveError) rather than capture it once.
- SCOPES (extension/identity.js:42-46) does not include the Sheets scope — only drive.file. Calling getAuthToken again after a partial grant returns the SAME token with no consent screen; identity.js:219-232 documents this and ensureScope() exists precisely because the cached token must be dropped first.
- window.fetch is monkeypatched at app.js:79-87, but localApiPath() (65-74) returns null for anything not under /api/, so googleapis.com calls fall through to nativeFetch untouched. Passing a googleapis request through api()/post() instead would attach a local deadline meant for the loopback engine.
- Both existing bars are repainted every POLL_MS = 1500 (app.js:2922) from the job poll — #act-bar by renderProgress (2967) and #mini-bar by renderMiniplayer (3159). Reusing either for an upload means a running crawl overwrites the upload's progress within 1.5 seconds.
- out() writes innerHTML (app.js:119-121), so an unescaped Google error message is an injection sink. Note the inconsistency already in the file: some sites esc() the message (1221, 1242, 1628) and some do not (805, 848, 1444, 2917) — copy the escaping ones.
- extension/tests/diagnostic-app-nomodule.html mirrors this markup (its view-settings at 1263, s-output at 1448, outputs at 1451). It is a byte-level twin of app.html for the no-module diagnostic and will drift if only app.html is edited.
- tools/panel_harness.py:59-66 hardcodes the /api/outputs fixture including the two "/sync" settings_url rows; a panel that expects new fields will render the harness's rows differently from the real engine's.

### Order this must be done in

1. 1. Decide the surface first: inside #s-output (app.html:1512-1516, beside the existing google row) or the empty Console shell (app.html:1287-1325). The rest of the order assumes #s-output.
2. 2. Add the markup — control + link target + a .bar/.bar-fill progress element — into app.html AFTER line 1515, never inside #outputs, because loadOutputs() overwrites that div's innerHTML.
3. 3. Create extension/sheets.js following drive.js's shape exactly: token as the first positional argument, {fetchImpl = fetch, onProgress = null} options, a SheetsError twin of DriveError (drive.js:66-73) and a refuse() twin (drive.js:92-113) so 401/403/5xx stay distinguishable.
4. 4. Import it in app.js's import block (line 15 neighbourhood, lines 10-19).
5. 5. Give it a render function next to loadOutputs() (app.js:3475-3518) so the new control is painted with the rest of the outputs area — and call that render from the same place, so nothing depends on a second load path.
6. 6. Wire the click in wireDeferredControls() (app.js:4380-4589), near the other openTab/action bindings around 4526 and 4570-4576. The handler reads state.token (app.js:140) and passes it in; it must not copy the token anywhere.
7. 7. Point sheets.js's onProgress at the new bar element with a small writer modelled on renderProgress() (app.js:2967-2995) — a separate function, since renderProgress is bound to job.fetch and is overwritten by the 1.5s poll.
8. 8. Route every rejection through out("<new-msg-id>", "...: " + esc(err.message), "err") (app.js:119-121), matching app.js:1241-1244.
9. 9. Only then decide what happens to the openTab("/sync") handoff at app.js:3514 — the google row still needs an action while the panel-side feature is incomplete, and its data-setup value is the engine's, not the panel's.

### Traps

- publish.SheetSink (19-34) looks like "the Google sink protocol" but localsheets.LocalSink implements it and publish_source is typed on it. Deleting it deletes the Excel export.
- publish._sink_batch (58-71) is named in the same breath as GoogleSink in its own comment, but it exists FOR LocalSink: it is what makes a whole export one file read and one file write. Removing it silently reintroduces four full-workbook rewrites per export (BACKLOG ت5, fixed in 0a2209c) — no test failure, just slow.
- publish.workbook_tables (74-104) has "pushed to Google" in its docstring but is the single definition of what an export CONTAINS for three survivors: outputs.apps_script_send (280-283), webui/app.py:997 (Data-page download) and LocalSink. publish._about (107-147) is reachable only through it.
- outputs._module_available (68-70) probes googleapiclient at line 432 AND openpyxl at line 94. It is not a Google helper.
- outputs.NotConfiguredError (55-60) is raised by excel_export and the Apps Script funnel and is what webui _integration turns into a 400. It is not the Google error class — GoogleNotConfiguredError (gdrive.py:34) is, and that one dies with the file.
- settings.py google_finance_auto_refresh / google_finance_refresh_hours (91-94) are the SCRAPED exchange-rate provider, not OAuth. They feed currency conversion, /data/google-finance, reports.browse_google_finance_rates, templates/google_finance_dataset.html and the settings-page section tests/test_settings_page.py asserts by name. Name-matching on "google" will eat them.

- all_destinations (outputs.py 524-537) is the registry: delete ONLY line 536. The local_db row at 531-533 is marked required:true and is what stops the UI presenting the database as switchable.
